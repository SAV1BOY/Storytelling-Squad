# Onboard New Storyteller

## Purpose

Provide a structured onboarding checklist for new team members joining the Storytelling Squad. This script ensures every new storyteller gains familiarity with tools, frameworks, agents, and workflows before contributing to live projects.

## Prerequisites

- New team member has accepted their role and has access to company email
- Squad lead has confirmed start date and assigned an onboarding buddy
- IT has provisioned accounts for collaboration tools (Slack, project management, shared drives)
- The story bank and swipe file repositories are accessible

## Steps

1. **Send Welcome Package (Day 0)**
   - Email the new storyteller a welcome message with links to this repository.
   - Share the `docs/getting-started.md` guide and `docs/glossary.md`.
   - Provide calendar invitations for onboarding sessions during Week 1.

2. **Set Up Tool Access (Day 1)**
   - Confirm access to the shared drive containing the story bank.
   - Grant permissions to the swipe file collection.
   - Add the new member to the `#storytelling-squad` Slack channel.
   - Verify access to the MMOS repository and this `squads/storytelling/` directory.

3. **Introduce Squad Structure (Day 1)**
   - Walk through the squad's mission, charter, and operating rhythm.
   - Review the 12 storytelling agents using `docs/agent-guide.md`.
   - Explain the relationship between scripts, docs, frameworks, checklists, and templates.

4. **Review Core Frameworks (Day 2)**
   - Read through the frameworks directory and `docs/framework-selection-guide.md`.
   - Discuss the Hero's Journey, StoryBrand, and Problem-Agitation-Solution patterns.
   - Complete a short exercise: identify which framework fits a sample brief.

5. **Shadow a Story Discovery Session (Day 2-3)**
   - Attend a live or recorded story discovery session (see `scripts/run-story-discovery-session.md`).
   - Take notes on facilitation techniques and question flow.
   - Debrief with the onboarding buddy afterward.

6. **Review Quality Standards (Day 3)**
   - Read `docs/quality-standards.md` and the scoring rubrics.
   - Review two past deliverables: one that passed the quality gate and one that required revision.
   - Discuss common pitfalls with the onboarding buddy.

7. **Practice a Customer Interview (Day 4)**
   - Role-play a customer interview using `scripts/conduct-customer-interview.md`.
   - Record the practice session for self-review.
   - Receive feedback from the onboarding buddy on question technique and active listening.

8. **Explore the Story Bank (Day 4)**
   - Navigate the story bank structure using `docs/story-bank-operations.md`.
   - Add one practice entry to the sandbox section of the story bank.
   - Learn tagging conventions and metadata requirements.

9. **Attend Cross-Squad Orientation (Day 5)**
   - Meet representatives from Copy, Brand, and Traffic squads.
   - Review `docs/cross-squad-integration.md` for handoff protocols.
   - Understand how storytelling deliverables flow downstream.

10. **Complete Onboarding Assessment (End of Week 1)**
    - Submit a short narrative piece using a provided brief and selected framework.
    - Run it through the quality gate process (`scripts/story-quality-gate-process.md`).
    - Receive written feedback from the squad lead.

11. **Set 30-Day Goals (End of Week 1)**
    - Collaborate with the squad lead to define three measurable goals for the first month.
    - Identify one framework and one agent to specialize in.
    - Schedule the 30-day check-in meeting.

12. **Join the Operating Rhythm (Week 2)**
    - Attend the first weekly squad standup.
    - Pick up a starter task from the backlog.
    - Begin contributing to the story bank with real entries.

## Expected Output

- New storyteller has full tool access and repository permissions.
- Completed onboarding assessment deliverable with feedback.
- Documented 30-day goals agreed upon with the squad lead.
- New member is active in Slack, attending standups, and contributing to the story bank.

## Troubleshooting

| Issue | Resolution |
|---|---|
| Tool access delayed by IT | Escalate to squad lead; use shared screen sessions in the interim |
| New member feels overwhelmed by frameworks | Focus on one framework first; schedule extra time with buddy |
| Onboarding buddy unavailable | Squad lead assigns a temporary replacement within 24 hours |
| Assessment deliverable does not pass quality gate | Provide detailed feedback and allow a second attempt before Week 2 |
| Cross-squad contacts unresponsive | Squad lead reaches out to peer squad leads directly |
