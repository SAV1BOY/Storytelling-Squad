# Swipe File Curation Guide

## Purpose

Explain how to curate and maintain the swipe file collection — a library of excellent storytelling examples from across industries, formats, and channels. The swipe file is a learning tool for the squad, a source of inspiration during creative blocks, and a reference for calibrating quality expectations.

## What Is a Swipe File

A swipe file is a curated collection of examples that demonstrate effective storytelling techniques. These are not assets to copy — they are assets to study. Each entry in the swipe file is annotated with why it works, which techniques it demonstrates, and how those techniques can be adapted for the squad's work.

## Swipe File Structure

### Folder Organization

```
swipe-file/
  hooks/
  characters/
  conflict/
  transformation/
  data-stories/
  visual-narrative/
  brand-stories/
  pitch-narratives/
  micro-stories/
  cross-channel/
  _index.md
```

Each folder corresponds to a storytelling skill or technique, not a format or channel. This makes the swipe file useful for learning specific skills.

### Entry Format

Every swipe file entry follows this format:

```
# [Title of the Example]

**Source:** [URL, publication, or origin]
**Date Added:** [YYYY-MM-DD]
**Added By:** [Squad member name]
**Category:** [Folder name — hooks, characters, etc.]
**Tags:** [Industry, format, framework, technique]

## The Example
[The full text, screenshot, or link to the original]

## Why It Works
[2-3 paragraphs explaining the specific techniques used and why they are effective]

## Key Techniques
- [Technique 1]: [Brief explanation]
- [Technique 2]: [Brief explanation]
- [Technique 3]: [Brief explanation]

## How to Adapt
[1-2 paragraphs on how the squad could apply these techniques to our work]

## Related Entries
[Links to other swipe file entries that demonstrate similar or complementary techniques]
```

## What to Collect

### High-Priority Examples
- **Hooks** that stop the scroll: first lines, subject lines, opening slides that demand attention.
- **Character introductions** that create instant empathy: how a person is introduced in one paragraph.
- **Conflict escalation** that builds tension: how stakes are raised progressively.
- **Transformation arcs** that pay off: before-and-after stories with satisfying resolution.
- **Data storytelling** that makes numbers human: charts, visualizations, and narrative data.
- **Visual-narrative alignment** where images and words amplify each other.
- **Cross-channel narratives** that maintain a story across multiple touchpoints.

### Sources to Monitor
- Industry-leading blogs and content marketing sites.
- Award-winning ad campaigns (Cannes Lions, The One Show, D&AD).
- Bestselling nonfiction that uses narrative (business books, journalism, longform).
- TED talks and keynote presentations.
- Podcast episodes with exceptional storytelling structure.
- Email newsletters known for narrative quality.
- Social media accounts with consistently high engagement through storytelling.
- Competitor content that performs exceptionally well.

### What NOT to Collect
- Examples that are visually appealing but narratively empty.
- Examples that require extensive context to understand (the technique should be visible in the example itself).
- Examples that are ethically questionable (manipulative, misleading, or exploitative).
- Examples older than 5 years unless they are canonical (timeless technique demonstrations).

## Curation Workflow

### Adding an Entry (Any Squad Member, Anytime)

1. Encounter an example that demonstrates an effective storytelling technique.
2. Save the example (screenshot, copy text, bookmark URL).
3. Create a new entry file in the appropriate category folder.
4. Fill in all fields of the entry format, especially "Why It Works" and "Key Techniques."
5. Add the entry to `_index.md` with title, category, and date.
6. Share the entry in `#storytelling-squad` Slack channel with a one-line description.

### Quality Check (Monthly, Squad Lead)

1. Review all entries added in the past month.
2. Verify that "Why It Works" is substantive, not just "this is good."
3. Ensure entries are in the correct category folder.
4. Check for duplicates or near-duplicates.
5. Remove any entries that do not meet the quality bar.

### Deep Review (Quarterly, During Narrative Review)

1. Assess the balance of categories: are any over-represented or under-represented?
2. Identify gaps: which techniques are not well-represented in the swipe file?
3. Assign squad members to fill specific gaps in the next quarter.
4. Archive entries older than 3 years unless they are canonical.
5. Update the `_index.md` with current counts and category notes.

## Using the Swipe File

### During Creative Blocks
When a writer is stuck, browse the swipe file category related to the stuck point:
- Stuck on the opening? Browse `/hooks/`.
- Character feels flat? Browse `/characters/`.
- Story lacks tension? Browse `/conflict/`.
- Ending falls flat? Browse `/transformation/`.

### During Peer Review
When reviewing a draft and a specific dimension scores low, point the author to relevant swipe file entries:
- "Your hook could be stronger. See entries SF-012 and SF-045 for examples of counterintuitive data hooks."

### During Training
Use swipe file entries as teaching materials in workshops and onboarding:
- Assign 3 entries to new squad members during their first week.
- Use entries as prompts in improv workshops.
- Reference entries during framework selection discussions.

### During Voice Calibration
The swipe file can include examples of voice done well — both from within the brand and from others:
- Entries tagged with voice-related techniques help calibrate what "warm but not casual" sounds like in practice.

## Swipe File Metrics

Track these to ensure the swipe file remains useful:

| Metric | Target | Frequency |
|---|---|---|
| New entries per month | 5-10 | Monthly |
| Category balance | No category below 10 entries | Quarterly |
| Entry age | 80% less than 2 years old | Quarterly |
| Usage (entries referenced in reviews or workshops) | At least 5 references per month | Monthly |

## Contribution Expectations

- Every squad member contributes at least 2 entries per month.
- New squad members contribute 3 entries during their first month as a learning exercise.
- The squad lead ensures category balance and overall quality.
