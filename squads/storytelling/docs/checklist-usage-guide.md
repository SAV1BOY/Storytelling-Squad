# Checklist Usage Guide

## Purpose

Checklists convert expertise into executable steps. The Storytelling Squad includes multiple checklists embedded within components, rubrics, and scripts. This guide explains how to use them effectively in the review process, ensuring consistent quality and preventing recurring mistakes.

## When to Use This Guide

- Before starting any new story project (pre-flight checklists).
- During the drafting process at key milestones (quality gate checklists).
- During peer review to ensure nothing is missed.
- On a recurring schedule for narrative health maintenance.
- When onboarding new squad members who need to learn the review process.

## Types of Checklists

### Pre-Flight Checklists

Run these BEFORE starting a project or delivering content. Pre-flight checklists prevent wasted effort by ensuring all inputs are in place.

**Story Pre-Flight:**
- [ ] Story type selected (value, founder, customer, purpose, data)
- [ ] Audience defined (role, knowledge level, emotional state, decision stage)
- [ ] Channel confirmed (pitch, blog, email, social, keynote, case study)
- [ ] Success metric defined (what does "worked" look like?)
- [ ] Story source material gathered (interview notes, data, quotes, consent forms)
- [ ] Framework selected using `docs/framework-selection-guide.md`
- [ ] Voice Card reviewed for the target brand and channel
- [ ] Deadline confirmed and realistic given the scope

**Pitch Pre-Flight:**
- [ ] Total time confirmed and section timing calculated
- [ ] Audience decision criteria identified
- [ ] Competitive context understood
- [ ] Three proof points prepared and sourced
- [ ] Hook tested and scored above 70
- [ ] CTA is specific and singular
- [ ] Rehearsed at least 3 times with timing recorded
- [ ] Objection responses prepared for top 3 anticipated challenges

**Customer Interview Pre-Flight:**
- [ ] Background research completed (account history, usage, prior testimonials)
- [ ] Consent form ready for verbal or written confirmation
- [ ] Recording equipment tested with backup method available
- [ ] Question guide drafted with 10-12 open-ended questions in three acts
- [ ] General topics shared with interviewee in advance
- [ ] Calendar block includes 15-minute buffer

### Quality Gate Checklists

Run these DURING the creation process at key checkpoints. These align with the formal quality gate process in `scripts/story-quality-gate-process.md`.

**After First Draft:**
- [ ] Story structure validator passes all required checks
- [ ] At least one proof block per major claim
- [ ] Hook score above 60
- [ ] Character is named and dimensional (not a generic role)
- [ ] Conflict is present and escalating
- [ ] Transformation is measurable (before/after with specifics)
- [ ] Word count is within 10% of the target for the format
- [ ] Framework elements are all present (no gaps in the structure)

**Before Peer Review:**
- [ ] Self-assessment completed noting areas of confidence and concern
- [ ] All data points verified against original sources
- [ ] Quotes are accurately transcribed and attributed
- [ ] Read aloud once to catch awkward phrasing and pacing issues
- [ ] Voice Card attributes checked against the draft

**Before Final Delivery:**
- [ ] Quality gate score is 25 or above (see scoring thresholds)
- [ ] All reviewer feedback has been addressed or documented as intentional exceptions
- [ ] Clarity score above 80
- [ ] All proof points sourced and attributed
- [ ] At least one editing pass using trim rules applied
- [ ] CTA present, specific, and connected to the narrative resolution
- [ ] Formatted for the target channel (length, style, visual layout)
- [ ] Supporting materials packaged (data sources, images, consent forms)

### Cross-Squad Handoff Checklists

Run these BEFORE handing assets to Copy, Brand, or Traffic squads.

- [ ] Story bank status updated to "approved"
- [ ] Quality gate scorecard attached
- [ ] Handoff Brief prepared with all required fields
- [ ] All files assembled in the handoff folder with correct naming
- [ ] Receiving squad contact confirmed and available
- [ ] Handoff meeting scheduled (15 minutes)
- [ ] Constraints documented (language that must be preserved, legal restrictions)
- [ ] Feedback timeline agreed upon

### Maintenance Checklists

Run these on a RECURRING basis to maintain narrative health.

**Weekly:**
- [ ] Story bank entry statuses updated by all owners
- [ ] Any stale entries (no progress in 7+ days) flagged for the squad lead

**Monthly:**
- [ ] Spot-check one piece per channel against consistency rules
- [ ] Review story bank for aging content (no status change in 30+ days)
- [ ] Update any metrics that have changed in published stories
- [ ] Swipe file reviewed for new additions (`docs/swipe-file-curation.md`)
- [ ] Improv workshop scheduled or confirmed for the month

**Quarterly:**
- [ ] Full narrative consistency audit or narrative audit (`scripts/run-narrative-audit.md`)
- [ ] Story bank gap detection across personas, products, and journey stages
- [ ] Quality score trends reviewed and benchmarks updated
- [ ] Quarterly narrative report generated (`scripts/quarterly-narrative-review.md`)
- [ ] Voice calibration check — recalibrate if scores have declined
- [ ] Checklists themselves reviewed and updated (add, remove, or modify items)

## How to Use Checklists Effectively

### Rule 1: Run Them in Order
Items are sequenced deliberately. Skipping ahead creates gaps that compound later. For example, verifying data before the draft is written prevents structural rewrites after the review.

### Rule 2: Never Silently Skip Items
If an item does not apply to the current project, mark it N/A with a brief note explaining why. This creates a record that the item was considered, not overlooked.

### Rule 3: Use Them as Minimum Standards
Checklists ensure nothing falls through the cracks. They do not replace judgment or creativity — they complement them. A checklist pass is necessary but not sufficient for quality.

### Rule 4: Track Completion and Patterns
Keep a record of checklist completions for each deliverable. Over time, patterns emerge: items that frequently fail become training priorities. Items that always pass may be candidates for simplification.

### Rule 5: Update Checklists Quarterly
As the squad evolves, checklists should evolve too. During the quarterly narrative review, assess:
- Are there new failure modes not covered by existing items?
- Are there items that are always passed and can be removed to reduce overhead?
- Have new tools, frameworks, or processes been introduced that need checklist coverage?

### Rule 6: Share the Checklist with the Work
When submitting a deliverable for review, attach the completed checklist. This gives the reviewer context about what has already been verified and where to focus their attention.

## Common Mistakes with Checklists

1. **Treating the checklist as the whole review.** The checklist catches known issues; peer review catches unknown ones. Both are needed.
2. **Filling out the checklist after the fact.** Retroactive checkbox-ticking defeats the purpose. Run the checklist at the intended stage.
3. **Using one checklist for all project types.** Select the appropriate checklist for the deliverable; a pitch pre-flight is different from a case study pre-flight.
4. **Ignoring the maintenance checklists.** They prevent decay. Skipping monthly and quarterly checks leads to a degraded story bank and inconsistent voice.
